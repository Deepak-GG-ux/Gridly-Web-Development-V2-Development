    Selection

    How the stack gets chosen

    Four questions settle most technology decisions before a line of code is written.

    Does the content change often, and by whom?

    Rarely-changing content can live in structured data files. Content edited weekly by a non-developer needs an admin interface and a database behind it.

    Is there state to keep?

    Accounts, orders, bookings and submissions need a server and a database. A brochure site has none of that and should not carry the cost of it.

    Who maintains it afterwards?

    A stack the client's own developer can read beats a clever one they cannot. Maintainability outranks novelty.

    What does hosting allow?

    Static hosting cannot execute PHP. That constraint is settled at planning time, not discovered during deployment.
